# MP-11 Temporary Legal Analysis Branch - play and analyze a displayed position without mutating the stored game

> **Status:** done - Stage 6 independent validation, full read-only closeout, final human acceptance, and archival complete

- **Read trigger:** Read after the confirmed combined MP-11 decisions and before every MP-11 dispatch; re-read the applicable stage before execution.
- **Upstream:** [static-position to analysis master plan](../../../master-plans/static-position-to-analysis.md), [accepted MP-10 Plan](../../done/mp10-browser-evaluation/mp10-browser-evaluation.md)

## Outcome

From any displayed captured-game ply, a human can create and play a legal temporary analysis branch for either side, use an application-owned q/r/b/n promotion picker when required, inspect a separate compact SAN branch line, undo or reset it, continue through a complete legal self-play branch to a terminal outcome, and deliberately queue only the currently displayed position for durable reusable analysis. The captured game, corpus, occurrence-derived frequency, game-seen state, trainer eligibility, and existing evaluation rules remain unchanged.

## Scope

- **Included:** An application-owned interactive board variant that preserves the safe read-only adapter by default; bounded evidence of native react-chessboard pointer, touch, keyboard, and promotion limitations; a ground-up Base UI/Material responsive promotion picker; chess.js legal move application and rejection; immutable in-memory branch state from every displayed stored-game ply; separate branch-origin/current FEN and compact SAN presentation; Undo latest move; Reset to branch-origin game ply; no redo; disabled captured-game Previous/Next while a branch is active; immediate branch discard on other game/ply navigation or reset; castling, en passant, promotion, terminal classification, and complete six-field FEN transitions; explicit evaluation of only the currently displayed branch position; queue/result reuse; and strict analysis/corpus/trainer namespace proof.
- **Expected areas:** `frontend/src/features/board-adapter/**`, `frontend/src/features/viewer/**`, `tests/e2e/viewer-branch.spec.ts`, existing viewer and board Storybook/test surfaces, and focused additions under `backend/tests/features/evaluation/**` or `backend/tests/features/analysis/**` only when needed to prove the existing boundary. Backend product source is not expected to change; `backend/app/features/evaluation/**` is touched only if an existing contract defect is proven. Update this Plan during implementation and apply the bounded roadmap correction to `docs/master-plans/static-position-to-analysis.md` at closeout or its authorized documentation stage.
- **Excluded:** Auto-queen, promotion settings or preferences, free-form placement, spare pieces, clear-board, illegal moves, redo, standalone position save, branch persistence or provenance, automatic analysis or persistence, queue cancellation, new evaluation or position APIs, schema/migration changes, corpus or stored-game mutation, trainer or frequency changes, authentication/authorization, generic CRUD, dependency changes, copied experiment code, board-library replacement, custom replacement for native ordinary-move keyboard controls, browser-side engines, broader trainer work, Stage 2+ implementation in this planning request, unrelated refactors, `Scratch/`, completed historical records, commits, pushes, and formatter execution through `--fix`.
- **Preservation:** `/`, the shell, Material styling and repository tokens/conventions, safe FEN validation and error boundary, ordinary captured-game traversal when no branch is active, MP-10 deliberate Analyze/Update/Retry/reuse/stale/failure/no-cancellation behavior, exact six-field FEN identity, unrelated worktree changes, and the separation of corpus tables from analysis/evaluation tables. Retain `frontend/src/features/board-adapter/BoardAdapterNativeProbe.tsx`, its test, additive stories, and `tests/e2e/viewer-branch.spec.ts` as bounded Stage 1 evidence; their probe-only promotion acceptance is not product semantics. `experiments/mock-ups/promotion/` remains visual/reference material and is not canonical.
