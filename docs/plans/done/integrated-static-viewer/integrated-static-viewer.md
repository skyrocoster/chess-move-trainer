## What we're building & why

MP-05 turns the Storybook-only MP-04 adapter into a production page: a durable `/viewer` route inside the accepted responsive shell that safely displays the standard starting position through the adapter, with a viewer-owned workspace and context region. It also introduces production React Router composition, replaces the shell's native Status link with router-aware navigation, adds Viewer as the second real destination, and renders an explicit in-shell **Page not found** state for unmatched routes instead of silently redirecting to `/`. As a required part of MP-05 acceptance, the temporary MP-01 Foundation Check is removed after real shell, primitive, board, error, router, and viewer stories or consumers replace every compatibility proof it provided.

The milestone is staged into three separately-judgeable human-visible shipments so no stage is a giant undifferentiated blob: first the workspace composition is built and proven in Storybook (the established review surface used by MP-02 and MP-04), then the production route composition and router-aware navigation are wired and proven in the browser, and finally the temporary Foundation Check is retired and the full repository check confirms the milestone is clean. `/` keeps its status purpose throughout, and the board remains read-only.

## UX decisions

- **Viewer page heading:** the workspace shows a visible H1 **Position viewer** with **no subtitle**. The subcaption text shown in the stale non-canonical advisory HTML (`docs/design-guides/mp05-viewer-workspace-reference.html`) is **not** part of the decision and must not be copied into the implementation or stories.
- **Empty Context region:** on wide layouts the viewer workspace shows a balanced primary board column and a context column. The context panel holds temporary multi-line Context notes and is **visibly labeled Context**, but remains a **non-landmark** plain container: a plain element with a visible heading, with **no `<aside>`/complementary role and no accessible name that creates an assistive-technology landmark**. It must not appear as a landmark in the accessibility tree.
- **Constrained layout:** workspace reflow is driven by a **CSS container query on the workspace's available content width** (never the shell's viewport breakpoint); when the workspace container is narrow, the inline Context panel is hidden and a native collapsed Context disclosure is shown instead, keeping the board a bounded centered column (still a CSS container query on the workspace's own available width, never the shell viewport breakpoint).
- **Board:** the workspace renders the MP-04 `BoardAdapter` with the standard starting position, White at the bottom, visible coordinates, and the required contextual label (settled default: **Chess board: standard starting position, White at the bottom**; exact copy is not a design contract).
- **Page not found:** unmatched routes render an explicit in-shell **Page not found** state inside the shell's main-content boundary, reusing the shipped MP-02 feedback primitives, with no silent redirect to `/`.
- **Navigation:** the shell sidebar and drawer show **Status** and **Viewer** as router-aware destinations with the active destination marked via `aria-current="page"`; selecting a destination from the drawer closes it.
