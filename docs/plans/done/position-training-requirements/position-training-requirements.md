# Position training requirements - See which positions need practice and submit answers judged by the backend

> **Status:** done - all five stages accepted; the primary database is schema v2 and the approved real-data result is proven

- **Read trigger:** Read before changing the primary database schema, position training scoring, `/api/positions` training routes, or the current primary database for this outcome.
- **Upstream:** [`docs/grilling-docs/missed-opening-move-analysis.md`](../../../grilling-docs/missed-opening-move-analysis.md) is the approved behavior and output prototype. The user approved it on 2026-09-12. No visual evidence or `DESIGN.md` applies.

## Outcome
The backend calculates one current training requirement for each eligible canonical-position and preferred-move pair from all imported game encounters, combines it with decaying aggregate training credit, lets callers discover scored pairs through a compact filtered positions collection, and judges submitted moves itself. This gives a future Learn interface an explainable, durable source of truth without changing the existing position-insight operation.

The approved real-database fidelity anchor is:

- FEN `rnbqkb1r/pppppppp/5n2/8/4P3/8/PPPP1PPP/RNBQKBNR w KQkq - 0 1`
- trainer color `white`, preferred move `b1c3`, opening key `B02:Alekhine Defense`
- 86 eligible encounters: 28 hits and 58 misses
- at the default policy, `G = -204`; no aggregate row means effective `T = 0`, adjustment `0`, `R = -204`, and `training_required = true`
- 15 same-date correct answers are the minimum needed to make the pair non-required

2. **done** - [x] Implement parameterized scoring and read-only scored-position discovery.
   - **Depends on:** Stage 1 schema contract and focused proof.
   - **Owned paths:** New focused training-requirement models, scoring, validation, repository/service modules, and exports under `src/chess_move_trainer/database/positions/**`; focused tests such as `tests/database/positions/test_training_requirements_scoring.py` and `tests/database/positions/test_training_requirements_discovery.py`.
   - **Ordered actions:**
     1. Define an immutable validated scoring policy parameterized for later callers: finite target success strictly greater than `0.5` and less than `1`, and finite positive training-credit half-life. Defaults are supplied later by backend configuration, not embedded throughout calculations.
     2. Implement `G = hits - (target / (1 - target)) * misses`, `F(T) = T * abs(T)`, `R = G + F(T)`, and `training_required` exactly when `R < 0`. Implement the inverse signed-square calculation for the smallest additional whole correct-answer count that makes `R >= 0`, assuming no wrong answers, new games, or intervening decay.
     3. Implement signed exponential decay over whole calendar days with the configurable half-life applied to training adjustment/credit `F(T)`, not directly to `T`: `stored_adjustment = stored_T * abs(stored_T)`, `effective_adjustment = stored_adjustment * 2 ** (-days / credit_half_life_days)`, and `effective_T = sign(effective_adjustment) * sqrt(abs(effective_adjustment))`. Equivalently for finite signed `T`, `effective_T = stored_T * 2 ** (-days / (2 * credit_half_life_days))`. At 30 elapsed days under the default policy, positive or negative signed training adjustment is halved, not quartered. Reads calculate this effective state without writing, refreshing dates, or resurrecting old credit.
     4. Build live evidence from every stored occurrence where the game's trainer color is the canonical position's side to move, an outgoing move exists, the game has a usable start date, and a non-null preferred move was active on that UTC calendar date. Count repeated occurrences independently, including repeats in one game, and group by canonical position plus preferred move.
     5. At discovery `as_of`, expose only an evidence-backed pair whose preferred move is active then. Keep inactive historical pairs and aggregate rows stored for later reactivation. A position with no current move preference, explicit `no_preference`, or no eligible evidence is not a discovery item.
     6. Add `training_requirement_gt`, `training_requirement_gte`, `training_requirement_lt`, and `training_requirement_lte`; require at least one finite boundary, validate combinations, and apply bounds to unrounded `R`.
     7. Add paired `opening_key` and `opening_match=reached|deepest` validation using the stable `ECO:Name` key and the games API's reached/deepest semantics, including its greatest-ply then stable-key deepest tie-break. Opening filtering selects globally scored pairs by matching-game association; it must not recalculate hits, misses, or `G` from only matching games.
     8. Reject the whole discovery with a stale-state domain error when any current eligible pair after opening scoping has `training_updated_on > as_of`, before requirement filtering or pagination. Never omit such a pair or silently use its future state. Permit future `as_of` for read-only decay preview.
     9. Return deterministic pages ordered by canonical position identity, trainer color, then preferred-move UCI, with page default `1`, page-size default `50`, maximum `100`, and total metadata. Return policy once in the envelope and the approved compact item fields only.
     10. Keep full finite precision for calculations and stored balances. Apply range filters before presentation rounding; serialize derived floating response values as JSON numbers rounded to six decimal places.
   - **Focused proof:** Command-level timeout 120 seconds; Bash tool timeout `130000` ms: `timeout 120s .venv/Scripts/python.exe -m pytest tests/database/positions/test_training_requirements_scoring.py tests/database/positions/test_training_requirements_discovery.py -q`.

Positive and negative cases explicitly prove that one configured half-life halves signed `F(T)` and derives `effective T` through the inverse signed-square transformation; with the 30-day default, 30 elapsed days halve adjustment rather than quartering it.
